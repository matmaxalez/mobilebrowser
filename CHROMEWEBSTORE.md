## Permissions Justification

| Permission | Type | Justification |
|------------|------|---------------|
| `debugger` | permissions | Core feature ("Full" mode, default). When the user switches mobile view on for a tab, the extension attaches to **that tab only** to apply the same device emulation as Chrome DevTools' device mode: phone User-Agent and Client Hints, touch input, `pointer: coarse`, phone screen size and orientation. No other protocol domains are used; nothing is read from the page. It detaches when the user switches it off. |
| `declarativeNetRequest` | permissions | "Lite" mode (no debugging infobar): session-only rules scoped to the tab where the user enabled mobile view set a phone User-Agent / Client Hints request headers and tag that tab's document responses with the chosen device profile. Rules are removed when the user switches it off or closes the tab. |
| `scripting` | permissions | Lite mode fallback: runs the extension's own bundled script in frames of the emulated tab so the page's JavaScript sees a phone (navigator, screen, touch, pointer). No remote code. |
| `webNavigation` | permissions | Lite mode: detects when a frame in the emulated tab commits a navigation, so the phone profile is applied to every page the user opens in that tab. |
| `tabs` | permissions | Reads the current tab's URL to refuse internal pages (`chrome://`, Chrome Web Store) where emulation is not allowed; keeps emulation for tabs opened from an emulated tab; reloads the tab so the site receives the mobile request. |
| `storage` | permissions | Saves the user's settings (chosen phone, mode, view) and the activation status (a hash of the entered activation code) locally, and remembers which tabs are emulated for the current browser session. |
| `<all_urls>` | host_permissions | The user can switch on mobile view on any website they choose, so the extension must be able to modify requests and run its script on that site. It does nothing on pages where the user hasn't switched it on (the content script exits immediately when the tab isn't emulated). |
| `content_scripts` on `<all_urls>` (MAIN world, document_start) | content script | Must run before the site's own scripts so the page sees a phone from the first line of code. In tabs without emulation it only checks for the extension's own marker and exits. |

## Review Notes

### Known Issues / Limitations
- The extension requires an activation code (distributed by the publisher) before emulation can be switched on. For review, provide a code in the dashboard's "Test instructions" field.
- `debugger` permission triggers extra review scrutiny and an install warning; justification above explains it is limited to tabs the user explicitly enables. Chrome shows its standard "started debugging this browser" infobar in Full mode — this is expected and mentioned in the description.
- `<all_urls>` is required because the user picks any site to emulate; `activeTab` is not enough (emulation must persist across navigations and reloads in the tab, and in tabs opened from it).
- Lite mode: requests made by a site's own service worker are not covered.
- Internal Chrome pages and the Chrome Web Store cannot be emulated.
